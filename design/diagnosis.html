01 — 진단

지금 촌스러워 보이는 이유

취향 문제가 아니라 시스템 부재입니다. 아래 다섯 가지가 체감 품질의 대부분을 깎고 있습니다.

위계

전부 굵어서 아무것도 강조되지 않음

라벨·버튼·요약·눈썹 텍스트가 모두 800, 우선순위 뱃지는 900입니다. 강조가 기본값이 되면 위계가 사라지고, 화면이 소리를 지릅니다.

font-weight: 800 × 5곳 · 900 × 1곳 · 400 본문 없음

서체

타입 스케일이 없고 한글 자간이 뭉갬

제목은 최대 82px인데 다음 단계가 28px입니다. 근거 없는 점프죠. 여기에 letter-spacing:-.05em은 라틴 기준 값이라 한글에서는 글자가 서로 붙습니다.

clamp(42px, 8vw, 82px) → 28 → 24 → 19 → 13

색

팔레트가 아니라 그때그때 고른 값들

초록만 세 종류, 주황 계열 세 종류, 거기에 노란 뱃지까지 섞입니다. 게다가 크림 + 세리프 + 테라코타는 생성형 도구가 가장 흔하게 뱉는 조합이라 “어디서 본 화면”으로 읽힙니다.

#1f6b50 #31745a #99b8a7 · #d9663d #a33d1c #8a4228 · #fff2bf

형태

모서리 8종, 상자 안의 상자 안의 상자

한 화면에 radius가 여덟 가지 나옵니다. 패널(테두리+그림자) 안에 카드(테두리), 그 안에 인라인 편집, 또 그 안에 이력 박스가 들어가 깊이 위계가 무너집니다.

28 / 22 / 18 / 16 / 14 / 12 / 10 / 999px

반응

손대도 아무 반응이 없음

transition이 스타일시트 전체에 한 줄도 없고 :hover도 없습니다. 정적인 화면은 실제 완성도와 무관하게 싸게 보입니다. 입력창과 버튼 높이도 서로 안 맞습니다.

transition 0회 · :hover 0회 · input 12/14 vs button 9/12

빈 상태

계획이 없으면 그냥 빈 공간

실측했더니 .plan-list의 높이가 0이었습니다. 처음 들어온 사람은 Plan 패널과 Task 패널 사이의 여백만 봅니다. 첫인상이 여기서 결정됩니다.

plan-list · height 0px · top 1031px

02 — 방향

다이어리가 아니라 계측 기록장

이 앱이 실제로 하는 일은 “계획한 나”와 “실제의 나”의 차이를 재는 것입니다. 그렇다면 화면도 장식이 아니라 계측기처럼 생겨야 합니다. 세 가지 원칙으로 정리했습니다.

숫자는 숫자답게

예상·실제·차이·ID는 전부 고정폭 서체에 tabular-nums를 씁니다. 자리가 맞아야 비교가 되고, 비교가 이 앱의 존재 이유입니다.

강조색은 하나, 의미색은 둘

잉크 인디고 한 색만 강조에 씁니다. 나머지 색은 장식이 아니라 판정입니다. 호박색은 초과, 청록은 미달·완료. 색이 정보를 나르면 팔레트가 저절로 줄어듭니다.

차이를 글자 말고 형태로

“600분 예상 / 820분 실제”를 읽게 하지 말고, 기준선을 넘긴 막대로 보게 합니다. 아래 계획 카드 시안에 들어 있습니다.

05 — 제약

과제 조건이 잠근 것

docs/REQUIREMENTS.md와 docs/T06-ACCEPTANCE-MATRIX.md를 대조한 결과입니다. 매트릭스 상단에 “expectation을 삭제·약화·변경하지 말 것”이 명시되어 있어, 아래 다섯 가지는 디자인이 건드릴 수 없습니다.

검사 44개 중 DOM·클래스 의존 0건 — CSS 개편은 안전

backend/tests/acceptance/ 7개 파일 모두 API 레벨 테스트입니다. className / querySelector / document. 검색 결과 0건이고, 프론트엔드에 대한 유일한 의존은 test_card5_export.py가 index.html의 존재를 확인하는 것뿐입니다.

우선순위를 화면에 high로 표시 T06-C05
T06-C15		 색·굵기·형태는 바꿔도 됩니다. 리터럴 high를 “높음”으로 번역하면 안 됩니다. 첫 시안이 이걸 어겼고, 위 계획 카드에서 되돌렸습니다.
성공 기준 “44개 검사 통과” 정확 일치 T06-C06 라벨을 붙이려면 반드시 별도 엘리먼트로 분리해 원문 텍스트 노드를 오염시키지 않습니다. 시안을 그렇게 고쳤습니다.

디자인은 채점 항목이 아닙니다

공식 과제문에 디자인·UI·화면 완성도에 대한 언급은 한 건도 없고, 고정된 44개 ID 어디에도 없습니다. 이 작업은 점수를 올리지 않습니다. 다만 “남길 것”이 전부 화면 캡처(계획 화면·돌아보기 화면·공개 안내 화면)라서 제출 증거의 인상과 포트폴리오 가치는 달라집니다. 채점 대비 순수 투자라는 전제로 진행하고, 대신 44개 중 하나라도 깨뜨리지 않는 것이 절대 조건입니다.

차이 값의 부호 표기

T06-C32는 variance를 -40으로 기대합니다. 양수에 +를 붙이는 것은 괜찮지만, 음수는 반드시 ASCII 하이픈이어야 합니다. 지표 라벨에 쓰는 U+2212(−)를 값에 쓰지 않습니다.

06 — 적용

무엇을 어디까지 고치는가

이 시안을 승인하시면 아래 순서로 진행합니다. 위쪽 두 줄만 해도 체감 차이의 대부분이 나옵니다.

파일작업영향
src/styles.css 토큰 레이어 도입 — 색·간격·반경·타입 스케일을 CSS 변수로 정의하고 기존 하드코딩 값을 전부 치환. 굵기 정리, hover·focus·transition 추가, 다크 모드 블록 추가. 공개 안내 배너는 채도만 낮추고 위치·문구 유지. 마크업 변경 없음. 검사 영향 없음.
index.html Google Fonts 링크 추가 (Archivo / IBM Plex Sans KR / IBM Plex Mono), 폴백 스택 지정. 초기 로드에 폰트 요청 추가.
src/App.tsx 계획 카드에 예상 대비 실제 게이지 추가, 빈 상태 블록 추가, min-height:48px 땜빵 제거. 우선순위 high와 성공 기준 원문은 그대로 유지. T06-C05·C06 유지 확인 필요.
features/see/SeePanel.tsx 지표 카드에 부호와 판정 색 적용, 근거 건수 표시. 클릭 동작과 근거 레코드의 ID 표기는 유지. T06-C83·C32 유지 확인 필요.
features/tasks/TaskPanel.tsx 할 일 행 밀도 조정, 상태 버튼과 태그 칩 통일. 정렬 기준 문구와 우선순위 high 표기는 유지. T06-C20·C15 유지 확인 필요.

서체를 외부에서 받을지 번들할지

Google Fonts 링크는 공개 접근(T06-C01)이나 비밀값(T06-C58) 조건과 무관하지만, 공개 앱에 서드파티 CDN 의존이 하나 생기고 Render 콜드 스타트에서 글꼴이 늦게 바뀌는 게 보입니다. 폰트 파일을 저장소에 넣어 자체 호스팅하면 의존이 0이 됩니다. 결정이 필요합니다.

영상 반영은 아직 안 됐습니다

보내주신 두 영상은 제가 재생할 수 없어 제목만 확인했습니다. 위 진단은 전부 배포본과 소스를 직접 보고 뽑은 것입니다. 영상에서 인상 깊었던 지적을 몇 줄 적어 주시면 이 시안에 합쳐서 다시 정리하겠습니다.
